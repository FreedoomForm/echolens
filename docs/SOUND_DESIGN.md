# Звуковой дизайн EchoLens

Как устроен звуковой слой: что играет, почему именно эти записи, как они
обработаны и как добавлять новые.

## Три слоя звука (в порядке приоритета)

| Слой | Откуда | Когда звучит |
|---|---|---|
| 1. Нейро-текстура | Stable Audio Open Small / RAVE, генерация на устройстве | Только если включён тумблер и есть файлы моделей (опция для флагманов) |
| 2. **Библиотека записей** | `assets/sounds/` — 1930 реальных записей FSD50K | Основной путь, всегда готов |
| 3. Процедурный DSP | `TextureGenerator` (модальный синтез, грануляция) | Мгновенный резерв, пока слой 1/2 не готов; гарантия «звук есть всегда» |

Слои кроссфейдятся между собой — переключение источника не слышно как скачок.

## Три типа библиотечных записей

```
assets/sounds/
├── class/<класс>/     221 набор: «голос предмета»
│     clock/clock_00..07.ogg — тиканье, кошка — мурлыканье,
│     чайник — кипение, велосипед — щёлки втулки, машина — гул мотора
├── loops/<МАТЕРИАЛ>/  15 материалов × 10 вариантов: бесшовная «подложка»
│     WOOD/wood_00..09.ogg, METAL/... — для классов без своего набора
├── events/<МАТЕРИАЛ>/ 60 one-shot акцентов (0.9 с): «объект появился»
└── manifest.json      индекс: какие ключи → какие файлы (читает SampleLibrary)
```

Правило выбора в `AudioEngine.assignSlots`: у класса есть свой набор → играть
его (вариант выбирается по hash id объекта, чтобы одинаковые предметы звучали
разными записями); нет набора → материал-луп из LabelTable.

## Почему FSD50K и как записи отбирались

**FSD50K** (Zenodo 4060432) — 51 197 клипов Freesound с человеческой
разметкой, 200 классов онтологии AudioSet. Выбран как крупнейший открытый
датасет с *верифицированными* метками и per-clip лицензиями CC.

Требование к звуку — «менее шумные, более чёткие, более контрастные» —
реализовано пайплайном `tools/` (детали: docs/DEVELOPMENT.md):

1. **Кандидаты**: для каждого из 426 классов и 15 материалов — фильтр
   лицензий (только CC0/CC-BY, NC запрещён), приоритет CC0 и рейтингов
   «заметности» звука (pp_pnp из FSD50K).
2. **Гейты качества**: SNR > 9 дБ, клиппинг < 2%, отсечение тишины —
   шумные и мутные записи отбрасываются автоматически.
3. **Лучшее окно**: выбирается самое стабильное громкое окно 3–4.5 с.
4. **Бесшовный луп**: tail-head кроссфейд 80 мс — луп не «щёлкает» на стыке.
5. **Нормализация**: RMS −19 dBFS — все голоса выровнены, движок получает
   предсказуемый материал для микширования.
6. **Кодек**: mono 48 кГц OGG q3 (как у AudioTrack внутри приложения).

Итог: 1930 файлов / 48 МБ в APK. Пофайловая атрибуция (id, название,
аплоадер, лицензия) — `assets/sounds/ATTRIBUTIONS.md`; сводка —
THIRD_PARTY_LICENSES.md.

## Спатиализация (как один объект становится «звуком в мире»)

- **ILD-панорама**: равная мощность L/R по азимуту относительно головы.
- **ITD (Woodworth)**: контралатеральное ухо задерживается до ~0.62 мс —
  главный признак направления на низких частотах.
- **Тень головы**: контралатеральное ухо + низкочастотный фильтр; в режиме
  динамика тень глубже (компенсация отсутствия индивидуальной HRTF).
- **Дистанция**: громкость ↓ и воздушный LPF (fc = 12 кГц/(1+d²·0.16)) —
  дальние объекты тише и глуше.
- **Реверберация**: лёгкий Schroeder — выносит звук «из головы» в мир.
- **«Дыхание»**: медленный LFO громкости (0.2 Гц, ~25%) — параллельные голоса
  не сливаются в монотонный гул.

## Контрастность параллельных голосов (требование живого теста)

«Если передо мной 15 деталей — пусть 15 разных звуков разной громкости и
частоты приходят параллельно». Реализация:

1. **Разные записи** — вариант по hash id: два стула не звучат одинаково.
2. **Разный питч** — playback rate ×0.86–1.2 на объект.
3. **Разная громкость** — важность × близость × «дыхание» LFO.
4. **Разная частотная полоса** — воздушный LPF по дистанции + тень головы
   разводят спектры; естественные записи имеют разные центры тяжести
   (дерево — низ, металл — верх).
5. **Ограничение по вниманию** — конус ±30° понижает громкость периферии,
   оставляя сознательно отслеживаемыми 3–4 ключевых потока (Bregman).

## Как добавить/заменить запись

1. Положить OGG (mono 48 кГц, нормализованный) в соответствующий каталог.
2. Обновить `manifest.json` (ключ = EN-имя класса из LabelTable).
3. Если класс новый — добавить в `core/LabelTable.kt` (см. docs/DEVELOPMENT.md).
4. Полная регенерация библиотеки из FSD50K — docs/DEVELOPMENT.md.
