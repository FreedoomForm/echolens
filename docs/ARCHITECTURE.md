# Архитектура EchoLens

> Одна строка: **камера → «что где находится» → параллельные естественные звуки,
> привязанные к объектам в мире**. Каждый модуль ниже отвечает на вопрос
> «зачем он здесь», а не только «что он делает».

## Поток данных (одна сессия, 20 мс цикл)

```
CameraX (YUV кадр)
   │  FrameConverter — YUV→ARGB без аллокаций (GC = джанк = джанк в звуке)
   ▼
YoloDetector (ONNX)            DepthEstimator (ONNX)
   YOLOE-26s @640, 426 классов    Depth Anything V2 Small INT8 @308
   «что это»                      «насколько далеко»
   │ bbox + класс + confidence    │ карта относительной глубины
   ▼                              ▼
SceneTracker — мир, привязанный к голове ──────────────────────
   • bbox-центр + глубина → 3D-точка; IMU (гиро) → мировые координаты
   • треки живут до 6 с: объект не «мигает», когда детектор его потерял
   • гистерезис меток: нет скачков «чашка/миска» между кадрами
   │ List<TrackSnapshot> (id, класс, RU-имя, материал, азимут, высота, дистанция)
   ▼
AudioEngine (поток реального времени, блоки по 20 мс)
   1. Ранжирование треков: важность × близость × центральность → до 16 голосов
   2. Конус внимания: что «перед головой» звучит громче (психоакустика внимания)
   3. Источник звука на выбор: нейро-текстура (опция) → запись из библиотеки
      → процедурный DSP-резерв. Слои кроссфейдятся, звук не рвётся никогда
   4. Спатиализация: ILD-панорама + задержка ITD (Woodworth) + низкочастотная
      тень головы + воздушное поглощение с дистанцией + лёгкая реверберация
   5. Лимитер → AudioTrack 48 кГц стерео
   ▼
Динамик телефона (по умолчанию) или наушники
```

Параллельно работают: **AudioSceneService** (LifecycleService: камера, TTS,
вибрация, уведомления, настройки) и **MainActivity** (UI поверх сервиса).

## Карта модулей: что и зачем

| Модуль | Зачем существует | Ключевое решение и почему |
|---|---|---|
| `vision/FrameConverter.kt` | YUV_420_888 сенсора → Bitmap для детектора | Нулевые аллокации на кадр: сборка мусора в реалтайм-цикле даёт рывки кадра и звука |
| `vision/YoloDetector.kt` | Определяет ЧТО вокруг | Открытый словарь YOLOE (426 класса) как основной: незрячего интересует «чайник/шкаф/полотенце», а не только 80 классов COCO. Fallback-цепочка YOLO26-S/N для слабых телефонов |
| `vision/DepthEstimator.kt` | Оценивает НАСКОЛЬКО далеко | Моно-глубина дешевле стерео и работает на любом телефоне; калибровка по типовым высотам объектов (LabelTable) превращает относительную глубину в метры |
| `vision/SceneTracker.kt` | Держит объекты СТАБИЛЬНЫМИ во времени и пространстве | Мир привязан к гироскопу, а не к кадру: повернул голову — звук остался у объекта. Трекинг + гистерезис меток убирают «мигание» и хаос из неупорядоченных детекций |
| `core/LabelTable.kt` | Единая таблица «класс → RU-имя, материал, высота, важность» | Сгенерирована из словаря YOLOE (см. docs/DEVELOPMENT.md). Первые 80 записей = COCO-80, чтобы fallback-детектор говорил то же самое |
| `core/TextureLibrary.kt` | Словарь только для COCO-fallback и тест-пинга | Не путать с SampleLibrary! Это ручной словарь классов→материалов для резервных моделей. Основной путь идёт через LabelTable |
| `core/Data.kt` | Доменные типы (Material, MaterialSpec, HeadPose, TrackSnapshot) | Общий язык между vision и audio без взаимных зависимостей |
| `core/RuText.kt` | Русские фразы направления/дистанции для TTS | Продуктовое решение: голос сцены — русский (основная аудитория). UI-строки при этом в ресурсах (values/, values-ru/) |
| `head/HeadTracker.kt` | Повороты головы из GAME_ROTATION_VECTOR | Относительный yaw сессии: не зависит от магнитометра/севшего компаса — точность нужна только «относительно старта» |
| `audio/AudioEngine.kt` | Сердце приложения: микс до 16 голосов + спатиализация | AudioTrack float-стрим вместо SoundPool: нужен per-voice DSP (ITD-задержки, LPF, LFO), которого SoundPool не умеет. Константы перцептивной модели — именованные, см. ниже |
| `audio/SampleLibrary.kt` | Декодирует записи из `assets/sounds/` (OGG→48k float) | Единственный читатель `manifest.json`. LRU-кэш 48 сэмплов ≈ 27 МБ: скорость ответа при новых объектах без раздувания памяти |
| `audio/TextureGenerator.kt` | Процедурный DSP-синтез материалов | Резерв: звучит, если записи не декодировались. Гарантия «звук есть всегда» — критично для незрячего пользователя |
| `audio/SimpleReverb.kt` | Schroeder-реверб 58 строк | Внешализация: сухой бинаурал звучит «в голове», капля ревера выносит звук «в мир» |
| `audio/neural/*` | ОПЦИЯ: генерация текстур Stable Audio/RAVE на устройстве | Отключено по умолчанию; живёт отдельно, чтобы основной путь не зависел от 850 МБ моделей. Строки статуса здесь RU — осознанный долг, см. «Известные компромиссы» |
| `service/AudioSceneService.kt` | Владелец жизненного цикла сессии | Foreground-сервис: сцена должна работать при погашенном экране. Камера+TTS+вибро в одном месте, потому что все они «одна сессия» |
| `MainActivity.kt` | Настройки и диагностика | Опрос uiState() 2 раза/с — deliberately simple; TalkBack-friendly крупные переключатели |
| `assets/sounds/` | Библиотека 1930 реальных записей FSD50K | См. docs/SOUND_DESIGN.md |
| `assets/*.onnx` | 3 детектора + глубина | Встроены: приложение обязано работать офлайн с первого запуска |

## Почему звук — это записи, а не нейросеть и не биперы

1. **Скорость**: нейро-генерация — 20–40 с на текстуру; запись декодируется за миллисекунды.
2. **Семантика**: тиканье часов сообщает «это часы» без обучения; биперы vOICe-типа требуют месяцев (обсуждение — docs/RESEARCH.md).
3. **Различимость**: 15 объектов = 15 разных естественных источников с разным питчем,
   громкостью и «дыханием» — слух разделяет их по законам слуховой сцены (Bregman).

## Perceptual model constants (AudioEngine)

Константы вынесены в companion object с KDoc. Кратко и с мотивацией:

| Константа | Значение | Почему такое |
|---|---|---|
| `W_PROX_BASE / W_PROX` | 0.35 / 0.65 | Голос выбирается по важности × близости; база 0.35 не даёт далёкой важной вещи полностью замолчать |
| `W_CENTRAL_BASE / W_CENTRAL` | 0.3 / 0.7 | Центральные объекты приоритетнее периферийных (конус внимания) |
| `AIR_LPF_HZ / AIR_LPF_K` | 12000 / 0.16 | Воздушное поглощение: fc = 12 кГц/(1+d²·0.16) — далёкие объекты глуше, это и естественно, и помогает разделить голоса |
| `SHADOW_LPF_HZ` | 12000 | Потолок низкочастотной тени головы для контралатерального уха |
| `GAIN_SMOOTH` | 0.0045 | Сглаживание громкости голоса за ~200 мс — дециппер без артефактов |
| `SPATIAL_GAIN_SMOOTH` | 0.004 | Чуть медленнее для L/R — панорама не «дрожит» при поворотах головы |
| `EVENT_GAIN_BASE / SCALE` | 0.35 / 0.45 | One-shot акцент при новом объекте: слышимый, но не пугающий |

## Потоки и ресурсы

- **EchoLensAudio** — realtime-поток движка; никаких I/O внутри 20 мс блока
  (декодирование записей — в воркерах SampleLibrary).
- **EchoLensNeural** — фоновый синглтон-провижинер нейро-текстур; живёт весь
  процесс (обоснование в KDoc класса).
- **Основной поток сервиса** — камера-колбэки и TTS; детекция и глубина
  считаются в камерном executor, не в UI.

## Известные компромиссы (осознанные, не баги)

1. **Строки статусов нейро-пайплайна hardcoded RU** — тумблер опционален и
   выключен по умолчанию; миграция в ресурсы отложена до появления второго
   рабочего языка. Основной UI полностью локализован (values/, values-ru/).
2. **`AudioSceneService` — «толстый» класс** (камера+TTS+вибро+уведомления).
   Разделение запланировано после появления инструментальных тестов.
3. **Дистанция монокулярная** — точность ±30–50%; достаточна для громкости
   и фильтра, недостаточна для точной навигации (см. Ограничения в README).
4. **YOLOE — AGPL-3.0** — модель дистрибутируется отдельным файлом-ассетом,
   код приложения MIT (детали: THIRD_PARTY_LICENSES.md).
